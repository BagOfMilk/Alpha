# Карта взаємодій — як вона збирається

`docs/interaction-map.html` **генерується**. Не редагуй його вручну — перезапишеться.

```bash
node tools/map/build.mjs           # перезібрати
node tools/map/build.mjs --check   # лише перевірити, чи застарів файл (код повернення 1)
```

Перезбирання запускається само: хук `PostToolUse` з `.claude/settings.json` смикає
`tools/map/hook.mjs` після кожної правки `Assets/**/*.cs`, `docs/*.md` або самих
файлів у `tools/map/`. Хук мовчить, коли все пройшло гладко, і пише повідомлення,
якщо генератор впав або помітив розбіжність.

## Що звідки береться

| Шар карти | Джерело | Правиться |
|---|---|---|
| Секції, слоти, схильності, ресурси, архетипи і всі їхні числа | `Assets/**/*.cs` | у коді |
| Прогін першого дня | `DefaultContent` + `BalanceConfig` + `BaseGameDemo` | у коді |
| 11 із 20 розривів | автоперевірки за кодом і доками | у коді |
| Код-шар (типи і зв'язки між ними) | `tools/map/graph.json` | вручну |
| Дизайн-шар GDD v6 | `tools/map/graph.json` | вручну |
| Інші розриви (дизайн проти коду) | `tools/map/graph.json` | вручну |
| Верстка і поведінка сторінки | `tools/map/template.html` | вручну |

Додав слот, архетип або значення в enum — вузол, зв'язки і рядок прогону з'являться
самі, а зайва картка розриву («секція без слотів») зникне. Числа в описах
вузлів і у формулах завжди перераховуються з вихідників, застаріти не можуть.

## Числа в кожній статті

У кожного вузла є блок «Числа» — він збирається генератором і застаріти не може:

* **код** — рядки, публічні члени, скільки файлів типом користуються, для enum — скільки значень;
* **база** — коефіцієнти, стелі виробітку на стартових архетипах, значення `BalanceConfig`;
* **дизайн** — числа з GDD із посиланням на рядок; де GDD чисел не дає, так і написано;
* **усім** — вага в графі: скільки зв'язків входить і виходить.

Числа дизайн-шару лежать у `graph.json` у полі `gddNumbers` — їх витягували з GDD і звіряли
за текстом. Якщо GDD зміниться, позначка про розбіжність з'явиться в шапці карти (див. нижче).

В авторських текстах розривів числа підставляються через `{{имя}}` — список підстановок у
`build.mjs`, константа `VARS`. Так картка «Рада: шість дій проти одного слота» сама
перерахує виробіток місця в раді, коли зміняться коефіцієнти.

## Категорії розривів

Розрив — не синонім «немає логіки». Кожна картка позначена типом, і лікуються вони по-різному:

| Тип | Що це | Чиниться |
|---|---|---|
| **Немає логіки** | механіка описана в GDD, коду немає | писати код |
| **Дизайн ↔ код** | код є, але суперечить GDD | обрати одну модель |
| **Док ↔ док** | два документи проєкту суперечать один одному | правити документ |
| **Мертвий код** | оголошено, але ніде не використовується | підключити або видалити |
| **Числа в доках** | документація називає числа, яких код не дає | перерахувати таблицю |
| **Баланс** | код працює як написано, але числа дають не той ефект | крутити коефіцієнти |

## Що генератор перевіряє сам

Секції без слотів · ресурси без виробника і без витрат · одностороння економіка ·
поля `BalanceConfig`, яких не читає жодна формула · `ScriptableObject`-конфіг,
чий `ToConfig()` ніхто не викликає · значення `CompanionStatus`, які ніхто не
присвоює · лікування без джерела поранень · закриті слоти, які нічим відкрити ·
події без підписників · версія Unity проти GDD · таблиця досвіду в `BALANCE.md`
проти формули `ProgressionMath` · бойові стати у шкалі 0–100, що потрапили у формулу
виробітку поряд зі схильностями 0–7.

Плюс звірка авторського шару: якщо в `graph.json` записаний зв'язок між типами, а в
вихіднику цього типу немає — генератор про це скаже.

## Дизайн-шар може застаріти

`graph.json` зберігає відбитки `docs/GDD.md`, `DESIGN.md` і `BALANCE.md` у полі
`designCheckedAgainst`. Дизайн-шар із прози не виводиться, тому, коли документ
змінюється, генератор не переписує його мовчки — він ставить у шапці карти позначку
«дизайн-шар звірявся з іншою версією». Перечитав GDD і оновив `graph.json` —
онови і відбитки:

```bash
node -e "const fs=require('fs'),c=require('crypto');const g=JSON.parse(fs.readFileSync('tools/map/graph.json','utf8'));for(const p of Object.keys(g.designCheckedAgainst))g.designCheckedAgainst[p]=c.createHash('sha1').update(fs.readFileSync(p,'utf8')).digest('hex').slice(0,8);fs.writeFileSync('tools/map/graph.json',JSON.stringify(g,null,1))"
```

## Публікація артефактом

Сторінка в репозиторії — самодостатній документ. Для публікації артефактом потрібна
та сама сторінка без обгортки `<!doctype html>` (її додає платформа):

```bash
node tools/map/build.mjs --artifact /шлях/до/alpha-map.html
```
