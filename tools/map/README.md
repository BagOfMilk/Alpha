# Карта взаимодействий — как она собирается

`docs/interaction-map.html` **генерируется**. Руками его не правь — перезапишется.

```bash
node tools/map/build.mjs           # пересобрать
node tools/map/build.mjs --check   # только проверить, устарел ли файл (код возврата 1)
```

Пересборка запускается сама: хук `PostToolUse` из `.claude/settings.json` дёргает
`tools/map/hook.mjs` после каждой правки `Assets/**/*.cs`, `docs/*.md` или самих
файлов в `tools/map/`. Хук молчит, когда всё прошло гладко, и пишет сообщение,
если генератор упал или заметил расхождение.

## Что откуда берётся

| Слой карты | Источник | Правится |
|---|---|---|
| Секции, слоты, склонности, ресурсы, архетипы и все их числа | `Assets/**/*.cs` | в коде |
| Прогон первого дня | `DefaultContent` + `BalanceConfig` + `BaseGameDemo` | в коде |
| 11 из 20 разрывов | автопроверки по коду и докам | в коде |
| Код-слой (типы и связи между ними) | `tools/map/graph.json` | вручную |
| Дизайн-слой GDD v6 | `tools/map/graph.json` | вручную |
| Остальные разрывы (дизайн против кода) | `tools/map/graph.json` | вручную |
| Вёрстка и поведение страницы | `tools/map/template.html` | вручную |

Добавил слот, архетип или значение в enum — узел, связи и строка прогона появятся
сами, а лишняя карточка разрыва («секция без слотов») исчезнет. Числа в описаниях
узлов и в формулах всегда пересчитываются из исходников, устареть не могут.

## Числа в каждой статье

У каждого узла есть блок «Числа» — он собирается генератором и устареть не может:

* **код** — строки, публичные члены, сколько файлов типом пользуются, для enum — сколько значений;
* **база** — коэффициенты, потолки выработки на стартовых архетипах, значения `BalanceConfig`;
* **дизайн** — числа из GDD со ссылкой на строку; где GDD чисел не даёт, так и написано;
* **всем** — вес в графе: сколько связей входит и выходит.

Числа дизайн-слоя лежат в `graph.json` в поле `gddNumbers` — их вытаскивали из GDD и сверяли
по тексту. Если GDD поменяется, пометка о расхождении вылезет в шапке карты (см. ниже).

В авторских текстах разрывов числа подставляются через `{{имя}}` — список подстановок в
`build.mjs`, константа `VARS`. Так карточка «Совет: шесть действий против одного слота» сама
пересчитает выработку места в совете, когда изменятся коэффициенты.

## Категории разрывов

Разрыв — не синоним «нет логики». Каждая карточка помечена типом, и лечатся они по-разному:

| Тип | Что это | Чинится |
|---|---|---|
| **Нет логики** | механика описана в GDD, кода нет | писать код |
| **Дизайн ↔ код** | код есть, но противоречит GDD | выбрать одну модель |
| **Док ↔ док** | два документа проекта спорят между собой | править документ |
| **Мёртвый код** | объявлено, но ничем не используется | подключить или удалить |
| **Числа в доках** | документация называет числа, которых код не даёт | пересчитать таблицу |
| **Баланс** | код работает как написан, но числа дают не тот эффект | крутить коэффициенты |

## Что генератор проверяет сам

Секции без слотов · ресурсы без производителя и без трат · односторонняя экономика ·
поля `BalanceConfig`, которых не читает ни одна формула · `ScriptableObject`-конфиг,
чей `ToConfig()` никто не вызывает · значения `CompanionStatus`, которые никто не
присваивает · лечение без источника ранений · закрытые слоты, которые нечем открыть ·
события без подписчиков · версия Unity против GDD · таблица опыта в `BALANCE.md`
против формулы `ProgressionMath` · боевые статы в шкале 0–100, попавшие в формулу
выработки рядом со склонностями 0–7.

Плюс сверка авторского слоя: если в `graph.json` записана связь между типами, а в
исходнике этого типа нет — генератор об этом скажет.

## Дизайн-слой может устареть

`graph.json` хранит отпечатки `docs/GDD.md`, `DESIGN.md` и `BALANCE.md` в поле
`designCheckedAgainst`. Дизайн-слой из прозы не выводится, поэтому, когда документ
меняется, генератор не переписывает его молча — он ставит в шапке карты пометку
«дизайн-слой сверялся с другой версией». Перечитал GDD и обновил `graph.json` —
обнови и отпечатки:

```bash
node -e "const fs=require('fs'),c=require('crypto');const g=JSON.parse(fs.readFileSync('tools/map/graph.json','utf8'));for(const p of Object.keys(g.designCheckedAgainst))g.designCheckedAgainst[p]=c.createHash('sha1').update(fs.readFileSync(p,'utf8')).digest('hex').slice(0,8);fs.writeFileSync('tools/map/graph.json',JSON.stringify(g,null,1))"
```

## Публикация артефактом

Страница в репозитории — самодостаточный документ. Для публикации артефактом нужна
та же страница без обёртки `<!doctype html>` (её добавляет платформа):

```bash
node tools/map/build.mjs --artifact /путь/к/alpha-map.html
```
