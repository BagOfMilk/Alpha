# Инструменты: тесты ядра без Unity

## Зачем это

Ядро `Game.Core` намеренно спроектировано без зависимостей от движка
(asmdef: `noEngineReferences: true`, ни одного `using UnityEngine`). Благодаря
этому вся игровая логика — Напряжение, конвейер дня, слой сигналов, экономика,
прокачка — **компилируется и тестируется обычным .NET, без запуска редактора**.

Выигрыш: цикл правки занимает секунды, а не «открой Unity и посмотри». И
ассистент может проверять свой код сам, а не отдавать непроверенное.

## Как пользоваться

```bash
./tools/run-tests.sh            # прогнать все тесты
./tools/setup-dotnet.sh         # поставить .NET SDK (нужно один раз)
```

Или напрямую:

```bash
dotnet test tools/Alpha.Headless.sln
```

В облачных сессиях SDK ставится автоматически — см. `.claude/hooks/session-start.sh`.

## Как это устроено

| Файл | Что делает |
|---|---|
| `Game.Core.Headless/Game.Core.csproj` | Собирает ядро под `netstandard2.0`. Файлы **не копируются** — подключаются ссылкой на `Assets/_Project/Scripts/Core/**`, поэтому headless и редактор не могут разойтись |
| `Game.Tests.Headless/Game.Tests.EditMode.csproj` | Те же тесты, что видит Unity Test Runner. Имя сборки задано явно — от него зависит `InternalsVisibleTo` в ядре |
| `Game.Tests.Headless/UnityShim.cs` | Заглушка `UnityEngine.Application.dataPath` для архитектурных тестов, которые грепают исходники. Лежит **вне** `Assets/`, поэтому Unity её не видит |
| `Alpha.Headless.sln` | Чтобы `dotnet test` работал одной командой |

## Границы

Покрывается **только `Game.Core`** — это вся игровая логика (37 файлов из 42).

**НЕ покрывается `Game.Gameplay`**: там `MonoBehaviour` и `ScriptableObject`,
их проверяет только Unity. Сцены, префабы, импорт ассетов и сборка билда —
тоже только в редакторе.

Поэтому зелёные headless-тесты означают «логика верна», но не отменяют
проверку в Unity перед релизом.

## Важные тонкости

- **NUnit 3.14, не 4.x.** В четвёртой версии классический API
  (`Assert.AreEqual`, `IsTrue`, `Greater`, `IsEmpty`) переехал в `ClassicAssert`.
  У нас таких вызовов больше семидесяти — на 4.x всё развалится, и headless-версия
  тестов разойдётся с той, что гоняет Unity.
- **Имя тестовой сборки** обязано быть ровно `Game.Tests.EditMode`: в ядре стоит
  `[assembly: InternalsVisibleTo("Game.Tests.EditMode")]`, а тесты трогают
  `internal`-члены. Другое имя — и получите `CS0122` в пяти местах.
- **`.gitignore`** игнорирует `*.csproj` и `*.sln`, потому что Unity генерирует
  свои. Для `tools/` стоят исключения — иначе эти файлы молча не закоммитятся.
