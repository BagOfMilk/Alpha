# Баги: сбор, разбор, повторная проверка

Один файл на весь поток дефектов плейтеста. Здесь — **процесс** и **живой
список**; критерии «как должно работать» — в `docs/TESTPLAN.md`.

## 1. Как репортить

Без этих трёх вещей баг чаще всего невоспроизводим — и чинить его нечем:

1. **Сид кампании** (виден в сейве, поле `campaignSeed`) — весь поток
   случайностей кампании детерминирован сидом, с ним прогон повторяется.
2. **Автосейв** — `%USERPROFILE%\AppData\LocalLow\<company>\Alpha\autosave.json`
   (и `slot*.json`, если игрок сохранялся руками).
3. **Телеметрия** — весь каталог `…\Alpha\telemetry\`.

Шаблон записи (копировать в раздел 4):

```
### B-NN <короткое утверждение о неверном поведении>
- Комминт/билд: <хеш или дата билда>
- Сид: <число>   Тестер: <кто>   День кампании: <N>
- Шаги: 1) … 2) … 3) …
- Ожидалось: <из TESTPLAN, со ссылкой на пункт>
- Фактически: <что произошло>
- Вложения: autosave.json, session_*.jsonl
- Класс: софтлок | потеря данных | неверное правило | баланс | текст/UI
- Статус: NEW → REPRO → ROOT → FIX → VERIFIED
```

Заголовок — **утверждение о поведении**, а не эмоция: «после загрузки квест
начинается заново» вместо «сломались сейвы».

## 2. Приоритет — по последствию, не по симптому

| Класс | Что это | Реакция |
|---|---|---|
| **Софтлок** | Кампания не может продолжиться (нет выхода из панели, состояние залипло) | Чинить немедленно, до всего остального |
| **Потеря данных** | Прогресс/награда/решение исчезли или задвоились после сейва | Немедленно |
| **Неверное правило** | Код противоречит GDD/собственному комментарию | В текущую итерацию |
| **Баланс** | Правило верное, числа злые/скучные | Копить, крутить пачкой по `BALANCE.md` |
| **Текст/UI** | Непонятно, не видно, не объяснено | Копить; частота важнее тяжести (R5) |

Отдельная категория — **«не баг, а ограничение»**: сверить со списком в конце
`TESTPLAN.md` до того, как заводить запись.

## 3. Цикл разбора (root cause)

1. **REPRO.** Загрузить присланный автосейв, повторить шаги. Не воспроизводится —
   не закрывать: спросить сид/видео, пометить `NEED-INFO`. «У меня не
   повторяется» само по себе не диагноз.
2. **Падающий тест ДО фикса.** Свести к минимальному сценарию в
   `Assets/Tests/EditMode` (или PlayMode, если дело в сценах/UI). Тест обязан
   падать на текущем коде — иначе он проверяет не то. *Это ловит больше всего:
   в итерации 21 два бага поймали мои же новые тесты, до коммита.*
3. **ROOT: какой инвариант нарушен и ГДЕ он живёт.** Не «в какой строке упало».
   Найдя место, сразу `grep` по братьям-копиям того же условия — правка в точке
   падения оставляет остальные копии живыми. (Классика проекта: `IsAlive` вместо
   «за игрока» — одна и та же ошибка в шести местах, DESIGN §6.19.)
4. **FIX в корне.** Если корень — дублирование правила, свести к одному
   владельцу (предикат/метод), а не чинить каждое место.
5. **VERIFIED.** `powershell -File tools/run-tests.ps1` зелёный + вручную ровно
   тот кейс из репорта + пункт `TESTPLAN.md`, который его покрывает.
6. **Записать.** Изменилось правило — строка в `DESIGN.md`; изменились числа —
   `BALANCE.md`; вылез КЛАСС ошибок — урок в конце профильного раздела DESIGN
   (как §6.19/A0), чтобы он не вернулся другим боком.

## 4. Ритм

- Фиксы копятся **пачкой в итерацию**, а не по одному билду на баг.
- После пачки — новый билд (`tools/build.ps1`, тесты прогоняются автоматически).
- Повторная сессия — с **новыми** людьми: тот, кто уже играл, онбординг больше
  не проверяет.
- Баланс не крутить по одному тестеру: нужна выборка и телеметрия, иначе
  тюнинг гоняет числа туда-сюда.
