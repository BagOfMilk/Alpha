# Плейтест первого часа (итерация 17)

Методика «шлюза валидации» из GDD (Приложение В, строка про единый чек-пойнт):
**вертикальный срез боя + первый час игры** снимает большинство МОНИТОР-рисков
одним заходом. Цель — решить тезис GDD: **«игроку дорог его ростер и его город,
поданные через осмысленные бои»**. Если петля цепляет — есть игра; если нет —
сэкономлен год.

## 1. Формат

- **3–5 тестеров**, по одному, без подсказок ведущего (онбординг должен вести сам).
- Сессия ~60–75 минут: создание → пролог → город → первая вылазка → возвращение.
- Ведущий молчит и записывает моменты застревания; помогает только при жёстком блоке
  (и это фиксируется как провал онбординга).
- Билд: Boot/Campaign/Battle-сцены из репозитория (айронмен — на усмотрение
  тестера; хотя бы один прогон в айронмене желателен).

## 2. Что собирается автоматически (телеметрия)

Файлы `…/AppData/LocalLow/<company>/<product>/telemetry/session_*.jsonl` —
по файлу на сессию, одна строка = одно JSON-событие. Забрать у тестера ВЕСЬ
каталог `telemetry/`.

| Событие | Поля | Риск GDD |
|---|---|---|
| `campaign_start` | ironman, background | R12 (выборы старта) |
| `onboarding_step` | step | R5 — воронка первого часа: тайминги шагов |
| `quest_started/choice/check/finished` | quest, stage, option, success | R5/R12 — развилка пролога, гейты |
| `boss_seeded` | companion | R6 — путь «бросил своих» |
| `day_advanced` | gold, buildMat, population, tier, tension, readiness | Прил. Б — экономика дня |
| `expedition_departed` | node, squad | темп петли |
| `battle_started` | kind, node/encounter | — |
| `battle_ended` | rounds, attacks, hits/grazes/misses/crits, strikes, avgShownChance, playerDowns/Deaths, enemyDeaths | R7 (живучесть), R9, **R11** (hit-rate vs показанный шанс) |
| `save_loaded` | file | **сигнал save-scum**: reload после потерь = ростер дорог, но фрустрация |
| `report_acknowledged` / `campaign_ended` | outcome | R6 |

Пороговые ориентиры (из смуг BALANCE.md/GDD §17.1):
- Пролог начат ≤ 7-й минуты; первая вылазка ≤ 50-й; полный час ≈ вся петля.
- Бой: 4–8 раундов; |фактический hit-rate − avgShownChance| ≤ 10 п.п. на ≥30 атаках.
- Смерти в прологе: возможны, но НЕ поголовные (телеграф ставок работает, R5).
- Экономика: к концу часа игрок сделал ≥1 осмысленную трату (стройка/совет).

## 3. Что спрашивать после сессии (опросник тезиса)

Шкала 1–5 + свободный комментарий:

1. Был ли момент, когда стало жалко бойца? Кого и почему? (ростер дорог)
2. Хотелось ли перезагрузиться после потери? Перезагрузился? (цена решений)
3. Развилка пролога: понял(а) ли, что выбор что-то изменил? Что именно?
4. Город: что строил(а)/делал(а) и зачем? Было ли «моё» поселение? (город дорог)
5. Бой: доверял(а) ли показанному шансу? Был ли момент «нечестно»? (R11)
6. Где застрял(а) или скучал(а)? (R5)
7. Хочется ли продолжить кампанию завтра? (главный вопрос)

## 4. Решение тезиса

Собрать по каждому тестеру: воронку онбординга (тайминги `onboarding_step`),
исход пролога, смерти/раны и реакцию (`save_loaded` после потерь vs принятие),
ответы 1/4/7. Вердикт:

- **Тезис подтверждён**: ≥3 из 5 называют конкретного бойца/решение в вопросах
  1–4 И ≥3 отвечают «да» на вопрос 7 → следующий шаг — контент-итерации
  (данжи в UI, арки, экраны персонажа).
- **Тезис под сомнением**: смерти безразличны или город «декорация» → чинить
  подачу ставок (реакции, отчёт возвращения, цену смерти), НЕ добавлять систем.
- **Провал онбординга** (застревания до города): чинить ведение первого часа
  до любых других выводов — остальные данные загрязнены.

## 5. Тюнинг по итогам

Крутилки — `BalanceConfig`/`BALANCE.md` (расхождений код↔док на момент
итерации 17 нет). Хардкоды, которые могут понадобиться в тюнинге и потребуют
выноса в конфиг: состав финала 8/6/5 (+5/+10 точности) в `FinalBattle`, пороги
лояльности 25/50/75 (`Loyalty`), длительность Подавления, порог «Медицина ≥ 1»
стабилизации. Составы квестовых боёв — `CampaignScreenController.QuestEncounterEnemies`.
