# Баланс — формулы и «крутилки»

Все числа собраны в `BalanceConfig` (чистый C#) и продублированы в
`BalanceConfigAsset` (ScriptableObject для инспектора Unity). Меняешь там — меняется
вся игра. Ниже — формулы и стартовые значения, чтобы крутить осознанно.

## 1. Прокачка / опыт

**Порог опыта до следующего уровня:**
```
XpToNext(level) = round( XpBase * level ^ XpExponent )
```
Стартовые значения: `XpBase = 100`, `XpExponent = 1.5`, `MaxLevel = 20`.

| level | XpToNext | суммарно до уровня |
|------:|---------:|-------------------:|
| 1     | 100      | 0                  |
| 2     | 283      | 100                |
| 3     | 520      | 383                |
| 4     | 800      | 903                |
| 5     | 1118     | 1703               |
| 6     | 1470     | 2821               |
| 7     | 1852     | 4291               |
| 8     | 2263     | 6143               |
| 9     | 2700     | 8406               |
| 10    | 3162     | 11106              |

Таблица сверяется с кодом тестом `BalanceDocTests` — если поменять `XpBase` или
`XpExponent`, тест покраснеет и укажет, какие строки пересчитать.

- Больше `XpExponent` → круче кривая (поздние уровни дольше).
- На `MaxLevel` опыт перестаёт копиться.

**Очки характеристик за уровень:** `StatPointsPerLevel = 3`. Распределяются по
профилю роста архетипа (`GrowthProfile`) методом наибольших остатков — сумма
всегда точна, пропорции соблюдены.

## 2. Производство на базе

**Сырая выработка слота за цикл:**
```
Raw = BaseOutput
    + Primary(стат)   * OutputPerPrimaryPoint
    + Secondary(стат) * OutputPerSecondaryPoint
```
**Итог за цикл:**
```
Output = round( Raw * GlobalProductionMultiplier * [ранен ? InjuredProductionMultiplier : 1] )
```
Дефолты модификаторов: `GlobalProductionMultiplier = 1.0`,
`InjuredProductionMultiplier = 0.5`.

`GlobalProductionMultiplier` — главный рычаг общего темпа экономики: подними,
если игра ощущается слишком медленной, опусти — если ресурсы девальвируются.

### Коэффициенты слотов (стартовые, из `DefaultContent`)

| Слот                | Выход      | Primary (×)        | Secondary (×)      | Base |
|---------------------|------------|--------------------|--------------------|-----:|
| Место в совете      | Morale (пас.)| Leadership ×1.0  | Charisma ×0.5      | 2    |
| Фермы поселения     | Food       | Logistics ×1.0     | Charisma ×0.5      | 6    |
| Рынок поселения     | Supplies   | Charisma ×1.0      | Logistics ×0.5     | 4    |
| Верстак мастерской  | Materials  | Engineering ×1.2   | Tech ×0.4          | 3    |
| Иссл. стол          | Research   | Science ×1.3       | Tech ×0.3          | 2    |
| Койка лазарета      | Healing    | Medicine ×2.0      | Survival ×0.5      | 4    |
| Погрузочный док*    | Supplies   | Logistics ×1.0     | Engineering ×0.4   | 3    |
| Разведпост          | Intel      | Scouting ×1.0      | Will ×0.2          | 1    |

\* изначально закрыт (`UnlockedByDefault = false`) — требует постройки.

> Пример: инженер с `Engineering = 6`, `Tech = 5` на верстаке даёт
> `3 + 6×1.2 + 5×0.4 = 3 + 7.2 + 2.0 = 12.2 → 12` материалов/день.

## 3. Ролевой опыт за работу

```
RoleXp = round( RoleXpPerCycle * [хорошее соответствие ? WellSuitedXpMultiplier : 1] )
```
«Хорошее соответствие» = основной стат слота ≥ `AptitudeMatchThreshold`.
Дефолты: `RoleXpPerCycle = 20`, `AptitudeMatchThreshold = 5`,
`WellSuitedXpMultiplier = 1.5`.

Намерение: ставить людей «по профилю» выгодно вдвойне — и выработка выше, и
растут быстрее.

## 4. Восстановление

- **Естественная регенерация:** `BaseHealingPerCycle = 5` снимается с `InjuryPoints`
  каждого раненого за цикл, даже без лазарета.
- **Лазарет (Healing-слот):** добавляет лечебные очки = его `Output`, которые
  распределяются по самым тяжело раненным в первую очередь.
- При `InjuryPoints ≤ 0` напарник снова `Idle` (готов к работе/бою).

Рычаг темпа потерь: чем меньше `BaseHealingPerCycle`, тем дороже каждая рана и
тем важнее лазарет и осторожная игра в Дажах.

## 5. Содержание

```
FoodUpkeep = FoodUpkeepPerCompanion * (число напарников)
```
Списывается каждый цикл. Если еды не хватает — `FoodShortage = true` (зацепка
под штраф к морали). Дефолт `FoodUpkeepPerCompanion = 1`.

## 6. Бой (XCOM) — целевые значения (ещё не в коде)

Заготовка для итерации 2, чтобы формулы были согласованы заранее:

```
ШансПопадания% = Aim − Defense_цели − Укрытие + Высота + Фланг_снимает_укрытие + Дальность
Укрытие: половинное +20 к защите, полное +40
Фланг: укрытие = 0, +крит
Урон = rand(WeaponMin..WeaponMax); крит = WeaponMax + CritBonus
ИтогУрон = max(0, Урон − Armor); Dodge% → «скользящий» (−1..−2 урона)
ПроверкаВоли при панике: d100 vs Will
```
Эти числа поедут в тот же `BalanceConfig` (секция Combat) при реализации боя.

## 7. Как менять баланс на практике

1. **В коде/тестах:** правь дефолты в `BalanceConfig.cs`, гоняй EditMode-тесты —
   они ловят регрессии формул.
2. **В Unity:** создай ассет `Alpha → Balance Config`, положи на `BaseGameDemo`,
   крути слайдеры, жми Play, смотри отчёт по дням в консоли.
3. **Пресеты сложности:** просто несколько `BalanceConfigAsset` (Easy/Normal/Hard).
