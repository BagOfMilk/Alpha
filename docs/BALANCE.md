# Баланс — формули і «крутилки»

Усі числа зібрані в `BalanceConfig` (чистий C#) і продубльовані в
`BalanceConfigAsset` (ScriptableObject для інспектора Unity). Змінюєш там — змінюється
уся гра. Нижче — формули і стартові значення, щоб крутити свідомо.

## 1. Прокачка / досвід

**Поріг досвіду до наступного рівня:**
```
XpToNext(level) = round( XpBase * level ^ XpExponent )
```
Стартові значення: `XpBase = 100`, `XpExponent = 1.5`, `MaxLevel = 20`.

| level | XpToNext | сумарно до рівня |
|------:|---------:|-------------------:|
| 1     | 100      | 0                  |
| 2     | 283      | 100                |
| 3     | 520      | 383                |
| 4     | 800      | 903                |
| 5     | 1118     | 1703               |
| 6     | 1470     | 2821               |
| 7     | 1852     | 4291               |
| 8     | 2263     | 6143               |
| 9     | 2700     | 8406               |
| 10    | 3162     | 11106              |

Таблиця звіряється з кодом тестом `BalanceDocTests` — якщо змінити `XpBase` або
`XpExponent`, тест почервоніє і вкаже, які рядки перерахувати.

- Більше `XpExponent` → крутіша крива (пізні рівні довші).
- На `MaxLevel` досвід перестає накопичуватися.

**Очки навичок за рівень:** `SkillPointsPerLevel = 3`. Розподіляються за
профілем зростання архетипу (`SkillGrowthProfile`) методом найбільших залишків — сума
завжди точна, пропорції дотримані.

## 2. Виробництво на базі

**Сира виробка слота за цикл:**
```
Raw = BaseOutput
    + Primary(стат)   * OutputPerPrimaryPoint
    + Secondary(стат) * OutputPerSecondaryPoint
```
**Підсумок за цикл:**
```
Output = round( Raw * GlobalProductionMultiplier * [поранений ? InjuredProductionMultiplier : 1] )
```
Дефолти модифікаторів: `GlobalProductionMultiplier = 1.0`,
`InjuredProductionMultiplier = 0.5`.

`GlobalProductionMultiplier` — головний важіль загального темпу економіки: підніми,
якщо гра відчувається надто повільною, опусти — якщо ресурси девальвуються.

### Коефіцієнти слотів (стартові, з `DefaultContent`)

> Таблиця нижче — ітерація 1, до перебудови моделі персонажа. Чинні
> коефіцієнти живуть у `DefaultContent.AllSlots()`: Primary там тепер навичка,
> Secondary — атрибут, і схильностей на кшталт Leadership чи Logistics більше немає.

| Слот                | Вихід      | Primary (×)        | Secondary (×)      | Base |
|---------------------|------------|--------------------|--------------------|-----:|
| Місце в раді        | Morale (пас.)| Leadership ×1.0  | Charisma ×0.5      | 2    |
| Ферми поселення     | Food       | Logistics ×1.0     | Charisma ×0.5      | 6    |
| Ринок поселення     | Supplies   | Charisma ×1.0      | Logistics ×0.5     | 4    |
| Верстат майстерні   | Materials  | Engineering ×1.2   | Tech ×0.4          | 3    |
| Дослідн. стіл       | Research   | Science ×1.3       | Tech ×0.3          | 2    |
| Ліжко лазарету      | Healing    | Medicine ×2.0      | Survival ×0.5      | 4    |
| Вантажний док*      | Supplies   | Logistics ×1.0     | Engineering ×0.4   | 3    |
| Розвідпост          | Intel      | Scouting ×1.0      | Will ×0.2          | 1    |

\* спочатку закритий (`UnlockedByDefault = false`) — вимагає побудови.

> Приклад: інженер з `Engineering = 6`, `Tech = 5` на верстаті дає
> `3 + 6×1.2 + 5×0.4 = 3 + 7.2 + 2.0 = 12.2 → 12` матеріалів/день.

## 3. Рольовий досвід за роботу

```
RoleXp = round( RoleXpPerCycle * [гарна відповідність ? WellSuitedXpMultiplier : 1] )
```
«Гарна відповідність» = профільна навичка слота ≥ `SkillMatchThreshold`.
Дефолти: `RoleXpPerCycle = 20`, `SkillMatchThreshold = 5`,
`WellSuitedXpMultiplier = 1.5`.

Намір: ставити людей «за профілем» вигідно вдвічі — і виробка вища, і
ростуть швидше.

## 4. Відновлення

- **Природна регенерація:** `BaseHealingPerCycle = 5` знімається з `InjuryPoints`
  кожного пораненого за цикл, навіть без лазарету.
- **Лазарет (Healing-слот):** додає лікувальні очки = його `Output`, які
  розподіляються серед найважче поранених у першу чергу.
- При `InjuryPoints ≤ 0` напарник знову `Idle` (готовий до роботи/бою).

Важіль темпу втрат: чим менше `BaseHealingPerCycle`, тим дорожча кожна рана і
тим важливіший лазарет і обережна гра в Данжах.

## 5. Утримання

```
FoodUpkeep = FoodUpkeepPerCompanion * (кількість напарників)
```
Списується кожен цикл. Якщо їжі не вистачає — `FoodShortage = true` (зачіпка
під штраф до моралі). Дефолт `FoodUpkeepPerCompanion = 1`.

## 6. Бій (XCOM) — цільові значення (ще не в коді)

Заготовка для ітерації 2, щоб формули були узгоджені заздалегідь:

```
ШансПопадання% = Aim − Захист_цілі − Укриття + Висота + Фланг_знімає_укриття + Дальність
Укриття: половинне +20 до захисту, повне +40
Фланг: укриття = 0, +крит
Шкода = rand(WeaponMin..WeaponMax); крит = WeaponMax + CritBonus
ПідсумковаШкода = max(0, Шкода − Armor); Dodge% → «ковзний» (−1..−2 шкоди)
ПеревіркаВолі при паніці: d100 vs Will
```
Ці числа поїдуть у той самий `BalanceConfig` (секція Combat) при реалізації бою.

## 7. Як змінювати баланс на практиці

1. **У коді/тестах:** прав дефолти в `BalanceConfig.cs`, ганяй EditMode-тести —
   вони ловлять регресії формул.
2. **В Unity:** створи асет `Alpha → Balance Config`, поклади на `BaseGameDemo`,
   крути слайдери, тисни Play, дивись звіт по днях у консолі.
3. **Пресети складності:** просто кілька `BalanceConfigAsset` (Easy/Normal/Hard).
