# Баланс — формулы и «крутилки»

Все числа собраны в `BalanceConfig` (чистый C#) и доступны в инспекторе через
`BalanceConfigAsset` (он держит `BalanceConfig` как вложенное сериализуемое поле —
любое новое поле появляется в инспекторе само). Меняешь там — меняется вся игра.
Числа — стартовые **ПЛЕЙСХОЛДЕРЫ** из Приложения Б GDD; тюнятся в плейтесте.

## 1. Прокачка / опыт

**Порог опыта до следующего уровня:**
```
XpToNext(level) = round( XpBase * level ^ XpExponent )
```
Старт: `XpBase = 100`, `XpExponent = 1.5`, `MaxLevel = 20`.

| level | XpToNext |
|------:|---------:|
| 1 | 100 |
| 2 | 283 |
| 3 | 520 |
| 5 | 1118 |
| 10 | 3162 |

**Очки скилов за уровень:** `SkillPointsPerLevel = 3` — кладутся в нераспределённый
пул (`Companion.UnspentSkillPoints`), игрок тратит вручную (`SpendSkillPoint`).
Классов нет, **респека нет** (понижать скилы в геймплее нельзя).

## 2. Производные из атрибутов

Считаются в `DerivedStatCalculator` как БАЗА, затем сворачиваются с модификаторами
(гир/трейты/шрамы/состояния) в `ModifierAggregator`. Мелкие числа — намеренно.

| Производный стат | Формула | Дефолтные коэффициенты |
|---|---|---|
| MaxHp | `HpBase + Сила·HpPerStrength` | 4 + Сила·2 → **6…20** |
| ActionPoints | `round(ApBase + Ловкость·ApPerAgility)` | 8 + Ловк·0.2 → **8…10** |
| Accuracy | `AccuracyBase + Ловкость·AccuracyPerAgility` | 50 + Ловк·2 |
| Defense | `DefenseBase + Ловкость·DefensePerAgility` | 0 + Ловк·1 |
| Initiative | `Ловкость·.. + Смекалка·..` | Ловк·1 + Смек·1 |
| Carry | `CarryBase + Сила·CarryPerStrength` | 4 + Сила·1 |
| CritChance | `CritBase + Ловкость·CritPerAgility` | 5 + Ловк·1 |
| Armor | база 0 | от гира (модификатор) |
| Resolve | `Воля·ResolvePerWill` | Воля·1 (сокращает длительность состояний) |

> **Итог модификатора** = `round( (база + Σ flat) × (1 + Σ percent/100) )`, не ниже нуля.
> Каждый источник учитывается один раз — нет двойного счёта (US-18.2).

## 3. Бой (WL3) — целевые числа (для боевой итерации)

Уже в `BalanceConfig`, секция «Бой» (используются при реализации Эпика 3):

```
Пул AP 8–10; движение ~1 AP/клетка; атака 3–4 AP; способности 2–6 AP.
Попадание = скил/оружие − укрытие (полу −20 / полное −40) − дистанция.
Граза: шанс ≤15% → 50% урона; пол ≥85% (не сливается полностью).
Strike-метр: +1/попадание, гарантированный удар при 3.
Броня: −1..2 флэт (мелко); пробитие/Шред −N.
HP 6–20, урон 2–8. DoT 2–3 урона/ход × 2–3 хода.
Типы урона: уязвимость ×1.25–1.5, резист ×0.5–0.75.
Отряд из 4. Окно дауна на спасение: 2 хода.
```

## 4. Ранения и восстановление

- **3 тира → дни лечения:** Лёгкое 2, Серьёзное 5, Критическое 10
  (`InjuryDaysLight/Serious/Critical`). Серьёзное+ присваивает вечный шрам.
- **Скорость лечения за день:**
```
recovery/день = NaturalRecoveryPerDay (1)
              + [Лазарет укомплектован?] ( InfirmaryRecoveryPerDay (1)
                                          + Медицина_медика · MedicRecoveryPerSkillPoint (0.2) )
```
Чем меньше `NaturalRecoveryPerDay`, тем дороже каждая рана и важнее Лазарет/медик.

## 5. База: население и стройка

```
PopulationGrowthPerDay = 0.25     // пассивный рост (ускоряется Таверной/жильём)
ConstructionSmallDays  = 4         // малая стройка 3–5 дней
ConstructionLargeDays  = 10        // крупная 8–12 дней
ConstructionStages     = 5         // 5 визуальных стадий по таймеру
```
**Материалы базой не производятся** — золото и оба компонента приходят только с
вылазок/квестов (squad-loop кормит settlement-loop).

## 6. Создание персонажа / трейты

```
TraitSlots = 4   // фикс число активных трейтов; новый сверх лимита требует вытеснения
```
Шрамы слоты НЕ занимают и несбрасываемы.

## 7. Как менять баланс на практике

1. **В коде/тестах:** правь дефолты в `BalanceConfig.cs`, гоняй EditMode-тесты
   (`Window → General → Test Runner`) — они ловят регрессии формул.
2. **В Unity:** `Create → Alpha → Balance Config`, положи ассет на `BaseGameDemo`,
   крути числа в инспекторе, жми Play, смотри лист персонажа и петлю времени в консоли.
3. **Пресеты сложности:** несколько `BalanceConfigAsset` (Easy/Normal/Hard).
