# B07 · Екран виходу борця («титантрон»): генератор і програвач

`R/` = `Assets/_Project/Scripts/Gameplay/Ring/`, `T/` = `Assets/Art/Ring/Titantron/`. Залежить від B00 (`RingTheme`/`BrandTokens`). Поки немає У0 (протокол — `README.md`), шаблон виходу в `RingShow` не чіпати.

## Мета
Власник (06.11.2026): «титантроны изучи их в рестлинге и сделай генератор вкусный». Кожен борець (NPC і гравець) виходить під **власний ролик**, зібраний з рецепта, а не під один напис. «Смачний» = упізнаваний за 3 с, **влучає в біт**, різноманітний, дешевий для слабкого Android/UHD 620 (PERF-01).

**Назва.** «Titantron» — торгова марка WWE (за агрегатором Trademarkia: реєстрація кл. 28 чинна, кл. 9 «екрани для арен» скасована 2009 — впевненість середня, не юридична порада; `docs/research/RING_ENTRANCE_REFERENCES.md`, A1). У нових іменах коду, UI й документів — **«екран виходу»** (`EntranceScreen`; нейтральні — «відео виходу», entrance video, ramp screen); слово власника лишається в цитатах. (Нині `RingShow` кличе його «титантрон» — перейменувати м'яко, разом із заміною `SetTitantron`.)

## Рецепт → ролик
| Вхід | Звідки |
|---|---|
| `gimmick` | `career_gimmicks.json` (`monster`, `flyer`, `technician`, `showman`) |
| `role` | шлях: Герой → `hero`, Лиходій → `villain`, Бунтар → `rebel` (`path.face/heel/rebel`) |
| `tier` | щабель арени: `gym` · `hall` · `arena` (**нині в грі лише `gym`** — решту дає B06; для огляду — прапорець `-tron-tier hall|arena`) |
| `name`, `seed` | повне ім'я борця; `seed` = 0 (інший `seed` — інший вихід того ж борця) |
| `player` | чи це гравець (золото — лише йому, див. нижче) |

1. Пул = `{gimmick}_{role}_{tier}.json`; варіант = `FNV-1a 32 біти(UTF-8 «ім'я|seed») mod variants` (еталон — `golden.json → variantFor`).
2. **Тексти** (слоти): `nick` — те, що між «», або повне ім'я, якщо прізвиська немає; `full` — ім'я без прізвиська («Богдан Дуб»; порожнє — шар не малюється); `tag` — «{gimmick.*} · {path.*}» із `ui_uk.json`. Усе — `RingTheme.Caps()`; Sofia лише ВЕЛИКІ (її малі кириличні — болгарські форми).
3. **Кольори — слоти `$…`:** слот → ім'я токена за `kits.json` (`slots[role]`; для гравця поверх — `playerSlots`; для щабля `gym` поверх — `monoSlots`) → `RingTheme.<Pascal(токен)>` (`ink0` → `Ink0`, `cobaltText` → `CobaltText`). Золото — **лише** `$accent` і `$flash` гравця (охоронець `Kits_GoldBelongsToThePlayerOnly`). Нових кольорів немає.
4. **Прозорість** — лише кроки `0 · AlphaTronGhost 0,18 · AlphaTronDim 0,34 · AlphaTronMid 0,58 · 1` (нові токени `BrandTokens`).

## Формат ролика (специфікація програвача)
**Координати:** одиниця = висота кадру (512 px у RT 1024×512); x вправо, y вниз, початок — центр; кадр = 2 × 1 одиниці. Центр обертання/масштабу — центр шару.
**Час:** `beat = t · bpm / 60`; показ щабля ступінчастий: `beatShown = floor(t · fps) / fps · bpm / 60` (gym 6, hall 12, arena 30 кадр/с — і це дешевший режим). Ролик = ключові кадри до `introBeats` + модифікатори назавжди (петля). **Удар** — `hitBeat` (gym/hall 2, arena 4): `HitTimeSec = hitBeat · 60 / bpm`.
**Шари** — масив, порядок = малювання знизу вгору. Поля: `id`; `k` ∈ `rect · plate · disc · ring · sprite · text`; статичні `x y s sx sy rot a clip w h`; `tint`; `fixed` (не тремтить); `flipx`; `tr` (доріжки); `mod` (модифікатори).
- `rect` — колір заливки; `plate` — паралелограм (`slant`° — верхня грань зсунута праворуч на `tan(slant)·h`, `w` — довжина горизонтальної грані; **Painter2D один раз**); `disc` — еліпс; `ring` — контур товщиною `t`; `sprite` — `background-image` + `-unity-background-image-tint-color`, для плиток `tile` (висота плитки, ширина за пропорцією, `background-repeat`, зсув `(ox, oy)`); `text` — `Label`: `slot`, `font` (ключ `kits.fonts`), `size` (одиниці висоти), `fit` (макс. ширина, пропорційне стиснення — `unityTextAutoSize` або вимір), `fill`, `shadow [тінт, dx, dy]` (жорстка, без blur), `outline`, `slant` (синтетичний italic), `tracking` (em), `hand` (у `gym` — Amatic ×1,35).
- `rot` — градуси за годинниковою; `clip` ∈ 0..1 — відкриття зліва направо до обертання (контейнер `overflow:hidden`).
**Доріжки** `tr: {prop: [[біт, значення, плавність?], …]}`, `prop` ∈ `x y s sx sy rot a clip w h`. До першого ключа — його значення, після останнього — останнє; плавність діє на відрізок, що **приходить** до ключа: `l, o2, o3, i2, i3, io2, ob` (`ob` = outBack, c1 = 1,70158), `s` = ступінь (тримати попереднє до цього біта). Формули — у `TitantronAssetsGuardTests.Ease`.
**Модифікатори** `mod` (формули — `TitantronAssetsGuardTests.State`): `pulse [кожні, амплітуда, спад, старт]` · `spin [град/біт, старт]` · `sway [ax, ay, період, фаза]` · `rock [град, період, фаза]` · `drift [vx, vy, старт]` (плитки: зсув текстури, інші шари: зсув x, y) · `blink [парність, старт]` · `flick [кожні, тривалість, старт]` · `sweep [період, старт, x0, x1]`.
**Події:** `hit` (біт удару — для піро, світла, камери); `shake {b, amp, dur}` — глобальний зсув усіх шарів без `fixed`: `dx = amp·(1 − (beat − b)/dur)·sin(83,1·beat)·cos(41,7·beat)`, `dy = amp·(…)·cos(67,3·beat)·sin(29,9·beat)`.
**Приймання програвача:** на `golden.json` (`states`) стани шарів збігаються з Python у допуску 2e-3 — тест у Ring-сесії за зразком `Golden_LayerStatesMatchPython`.

## Що зробити в коді (сесія «Ринг»)
1. `TitantronPlayer` (UI Toolkit у `RingShow`-RT 1024×512, як нині): збирає дерево шарів із пулу, кожен кадр оновлює лише `translate / scale / rotate / opacity` (+ `clip`); **без blur, без перерахунку розкладки щокадру**; ≤ 30 шарів на екрані; плитки й спрайти — `Resources/Ring/Titantron/…` або Addressables за вашим вибором; імпорт спрайтів: sRGB, альфа, wrap `Repeat` для плиток (`tile: true` у `sprites.json`), ASTC.
2. `RingShow`: замість `SetTitantron(title, sub, color)` — `PlayEntrance(recipe)`. Затримка кадру на завісі — `max(2,2 с, HitTimeSec + 1,3 с)`; **піро й CO₂ (`RingFx.Entrance/TitleHit`) — на `HitTimeSec`**, а не на 0 / 0,35 с; `RingFx.Entrance(…, bpm)` бере `bpm` ролика (нині жорстко 120); світло екрана `_tronLight` — колір `$role` (не `Color.Lerp(…)` з літералів).
3. **RT з мипмапами:** `useMipMap = true`, `autoGenerateMips = true`, `filterMode = Trilinear`, `anisoLevel = 4` — тонкі лінії й растр (сканлінії 2 px/8 px, півтон 26 px, сітка 3 px) на екрані в 3D інакше мерехтять (муар; дослідження E3).
4. **Повтор скорочений** (F4, B5): перший вихід борця за сесію — повний; повторний — з `hitBeat − 1` (без тизера) і без `shake`. **Удар = перший звук** (B3): коли з'явиться тема виходу, її перший удар збігається з `HitTimeSec`; до того — короткий стінгер на `HitTimeSec`.
5. `GraphicsTier.Low`: один статичний ключовий кадр (`beat = introBeats`) + лише `pulse`, або `fps` ≤ 12.
6. Вступ (назва гри) — окремий рецепт у B01, **не** цей пакет; прибрати `#FFD966` і `Color(1f, 0.85f, 0.4f)` (поза токенами).

## Безпека й доступність (WCAG 2.3.1, XAG 117)
- Генератор гарантує: **рівно один шар-спалах** (`flash`) із прозорістю не вище `AlphaTronGhost` (різниця яскравості < 10 %), блимання лампочок/«збою» не частіше 3 разів за секунду, жодних білих полів на весь кадр. Охоронці — `selfcheck.py`, `Pools_FlashesStayBelowSafetyLimits`.
- **Перемикач «Менше руху»** (налаштування, за замовчуванням вимкнений): програвач ігнорує події `shake`, шар `flash` і модифікатори `spin · rock · blink · flick · sweep`, лишає `pulse` (≤ 3 %) і ступінчастий показ.
- Текст — у безпечній зоні 5–10 % від країв (плита ≤ 89 % ширини); ім'я стоїть без тремтіння ≥ 0,8 с після удару (`shake` спадає за ≈ 0,7 с).

## Приймання (У2)
Кадри з білду: **три рецепти × три щаблі** (монстр/лиходій/Палац · літун/герой/клуб · шоумен/бунтар/спортзал; усього 9, `-tron-tier`) на `HitTimeSec −0,2 · 0 · +0,3 · +2 с`; імена з Ґ Є І Ї (довге ім'я стискається `fit`, не переносить); ролик не накриває борця й рефері (у кадрі проходу екран бачимо над завісою); піро й спалах екрана на **одному** кадрі; Д1–Д6 (Статут §4), у першу чергу Д6: ≤ 30 шарів, жодного blur, жодного перерахунку розкладки щокадру. Директор приймає **очима**.

## Чому саме так (дослідження 06.11.2026)
Повний звіт з джерелами й впевненістю — `docs/research/RING_ENTRANCE_REFERENCES.md`. Підтверджено: сучасні виходи тримаються на **кортежі «ім'я · шрифт · палітра · символ · фірмовий рух»**, а не на монтажі (A5, G5); удар лежить на сітці бітів, «удар = перший звук» (B3); архетип читається мовою форм (C2); безпека спалахів — ≤ 3/с (C6). **Не знайдено:** стандартної структури й тривалості ролика, коду кольорів face/heel, інтерв'ю монтажерів — каркас «тизер → удар → ім'я → слоган → петля» є **нашою реконструкцією**, колір ролі — наше рішення (кобальт/кармін/рожевий).

## Не робити
Нових кольорів, шрифтів, слів у спрайтах, blur/glow, великих білих полів (яскравість LED), анімації через `fontSize`, золота в NPC.

## Відкриті питання (типово — у дужках)
1. Назва «екран виходу», `Titantron` — лише в цитатах (так). 2. Екран гравця — автоматично з гіміка й ролі (так); вибір «стилю виходу» при створенні — пізніше. 3. Золото на екрані гравця (`$accent`, `$flash`, тло «друкованого» зсуву плити) — за Статутом COL-02 це **ідентичність гравця**, не «успіх»; власник підтверджує. 4. Тема й BPM виходу — трек звуку: нині BPM задає гімік (100/132/112/120). 5. Прапор «чемпіон» (пояс на екрані) — після альфи. 6. **Різноманітність:** 4 варіанти на пул (дзеркало × заміна мотиву) — менше рекомендованих дослідженням 8–12 рукотворних рецептів на архетип (G2–G4); додавати рецепти — запис у `compose.py`, програвач не змінюється.

## Чого директор не перевіряв (чесно)
Рендер у Unity/UI Toolkit (весь перегляд — Pillow-композитор, що відтворює ті самі перетворення); синхрон з музикою (звуку в виходах ще немає); продуктивність на Android. Саме це закриває У2.
