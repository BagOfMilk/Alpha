# Звук «Рингу» — лише зі схвалення власника

Рішення власника 08.11.2026, дослівно: **«Выключи все звуки пока я не скажу обратного из всех будущих сборок. Собери мне
библиотеку всех треков где я смогу их заапрувить и тогда они идут в игру, если реджект нужны еще 3 пока какую-то не
выберу»**.

Це правило діє для **всіх майбутніх збірок** (і «Рингу», і архівної Alpha в тому самому проєкті), доки власник не скаже
інакше. Воно сильніше за попередні «Звук ок» до окремих треків: до схвалення в бібліотеці не звучить нічого.

## Як це працює в грі

- Список схвалених кліпів — `Assets/Resources/Ring/sound_approvals.json`, поле `approved`: назви кліпів (ім'я файлу без
  розширення, як `music_login`, `hit_01`). **Порожній список — уся гра мовчить.**
- `Gameplay/Ring/RingSoundGate.cs` — ворота: кожен програвач (`RingSound`, `RingMenuAudio`, Alpha `AudioDirector`) перед
  відтворенням питає `RingSoundGate.Allows(clip)`. На старті, поки нічого не схвалено, ще й `AudioListener.volume = 0` —
  тиша навіть для коду, що обійшов ворота. У `Player.log`: `[Звук] схвалено кліпів: N …` і по рядку на кожен
  кліп, якому відмовлено (`[Звук] не схвалено — мовчить: …`).
- Модель — `Gameplay/Ring/Models/RingSoundApproval.cs`: зіпсований чи неповний файл = тиша (звук без схвалення гірший
  за тишу).
- Охоронці — `RingSoundApprovalTests`: порожній список мовчить; схвалене грає точно за назвою; зіпсований файл —
  тиша; у списку лише назви наявних звукових файлів; **кожен файл, що грає звук через `AudioSource`, ходить через
  `RingSoundGate.Allows`** (новий програвач повз ворота — червоний тест; перевірено мутацією 08.11.2026).

**Новий звук у грі** (нова тема, новий удар, озвучка) додається так: файл → бібліотека (новий слот) → схвалення
власника → назва в `sound_approvals.json`. Програвач — лише через `RingSoundGate.Allows`. Яка подія матчу що грає —
таблиця `docs/ring/audio/EVENT_SOUND.md` (`RingSoundMap`, критерій М1 «без порожніх подій»).

## Процес

1. Власник слухає й вирішує на сторінці.
2. На «перевір бібліотеку звуку» Claude читає рішення:
   - **схвалено** поточний варіант → назва кліпу йде в `sound_approvals.json` (коміт, у наступній збірці звучить);
   - **схвалено** новий варіант → його файл замінює файл слота в грі під тією самою назвою і з тим самим розширенням
     (`.meta` і посилання сцени не змінюються; OGG/MP3 кодує `soundfile` у службовій теці), ліцензію — в LICENSE/LICENSES
     поруч; для нових звуків подій файлу ще немає — WAV кладеться в `Assets/Art/Ring/Sound/Resources/RingSound/<слот>.wav`;
     назва слота — в `sound_approvals.json`;
   - **усі варіанти слота відхилено** → Claude робить **3 нові** (з урахуванням приміток), додає їх у каталог і
     перепубліковує сторінку; так доти, доки власник не обере.
3. Нові варіанти — власна генерація (`tools/ring_audio`) або CC0 (дозвіл власника на пошук CC0-звуку — 04.11.2026);
   жодних чужих мелодій і назв. Кожен раунд описаний у `tools/ring_audio/library/rounds/round_<N>.json` (id `<слот>.v<k>`, наскрізно:
   раунд 1 — v1–v3, раунд 2 — v4–v6…; підпис, що інакше, як відтворити); генератори — `tools/ring_audio/ring_*.py`, рендер детермінований.
