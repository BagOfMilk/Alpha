# Тест-план: критерии приёмки механик

Дополняет `docs/PLAYTEST.md` (там — методика живой сессии и опросник тезиса).
Здесь — **что считается правильной работой механики**: наблюдаемый результат, по
которому баг отличается от «так задумано».

Источник истины по правилам — `docs/GDD.md`; числа — `docs/BALANCE.md`; как
реализовано — `docs/DESIGN.md`. Этот файл ничего нового не решает: он превращает
их в проверяемые утверждения и говорит, **где** каждое проверяется.

## Как читать таблицы

- **Авто** — закрыто автотестом (`tools/run-tests.ps1`, 304 EditMode + 7 PlayMode).
  При регрессии тест падает; вручную такие строки перепроверяют только после
  правок в этой области.
- **Ручной** — автотестом не берётся: UI-поток, читабельность, межсценные
  переходы, поведение при выходе из игры. Это и есть чеклист сессии.
- **Телеметрия** — проверяется постфактум по `session_*.jsonl`.

Пометка ⚠ — либо известное ограничение (список внизу), либо дыра в покрытии:
поведение реализовано, но живёт в UI-слое, автотестом не закрыто и держится
только на ручной проверке. Такие строки — первые кандидаты в PlayMode-тесты.

## Известные ограничения (НЕ баги)

Отложено сознательно, зафиксировано в `docs/DESIGN.md` §6.18–6.19:

- **Айронмен-чекпойнт только для вылазок.** Выход из проигранного КВЕСТОВОГО боя
  всё ещё откатывается загрузкой.
- **Влияние почти не набирается** — Дипломатия в совете практически недостижима.
- **Сташ без веса и лимита** — сложить можно сколько угодно.
- **Моды и аугменты (US-6.4)** не реализованы: крафт умеет только апгрейд редкости.
- **Данжи не выведены в UI** — `DungeonRun` играется только демкой.
- **Рекрутинг не реализован**: ростер только убывает.

## Что делать с найденным

Порядок разбора — `docs/BUGS.md` (шаблон отчёта и цикл «корень → фикс →
регрессионный тест → повторный прогон»). Коротко: репорт без **сида кампании,
автосейва и telemetry-файла** не воспроизводится, а значит, чинить его нечем.
